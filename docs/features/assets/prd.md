# Product Requirements Document (PRD)
## ระบบบริหารจัดการพัสดุและครุภัณฑ์ (Asset & Inventory Management)

---

### 1. บทนำและวัตถุประสงค์ (Objective)
ระบบบริหารจัดการพัสดุและครุภัณฑ์เป็นฟีเจอร์หลักในการควบคุม ตรวจสอบ และบริหารจัดการทรัพย์สินของคณะ ทั้งครุภัณฑ์ถาวร (Capital Assets) และวัสดุสิ้นเปลือง (Consumable Supplies) เพื่อความโปร่งใสตามระเบียบพัสดุภาครัฐ ลดความสูญหาย และเพิ่มประสิทธิภาพในการจัดสรรทรัพยากร

**เป้าหมายหลัก:**
1. รวมศูนย์ข้อมูลทะเบียนครุภัณฑ์ทั้งหมดของคณะไว้ในระบบเดียว แยกตามสังกัดภาควิชา/หน่วยงานภายใต้ระบบ Multi-tenancy
2. จัดการวงจรชีวิตครุภัณฑ์ (Asset Lifecycle) ตั้งแต่การรับเข้า, การจัดทำรหัส/สแกน QR Code, การโอนย้ายผู้ครอบครอง, การส่งซ่อม, จนถึงการแทงจำหน่าย (Disposal)
3. บริหารคลังวัสดุสิ้นเปลือง พร้อมระบบแจ้งเตือนสต็อกใกล้หมด (Safety Stock Alert) และควบคุมการเบิกจ่าย
4. บันทึกประวัติการเปลี่ยนแปลง (Audit Trail) แบบไม่สามารถลบหรือแก้ไขย้อนหลังได้ เพื่อการตรวจนับพัสดุประจำปี

### 2. กลุ่มผู้ใช้งานและสิทธิ์การเข้าถึง (User Personas & Roles)

| Persona / Role | คำอธิบายและบทบาทหน้าที่ | หน้าจอหลักที่ใช้งาน |
| :--- | :--- | :--- |
| **Guest / ผู้ใช้ทั่วไป** | สแกน QR Code บนตัวครุภัณฑ์ผ่านสมาร์ทโฟน เพื่อตรวจสอบข้อมูลครุภัณฑ์พื้นฐาน สถานะ และหน่วยงานที่รับผิดชอบ | Public Page (`/asset-qr/[id]`) |
| **Staff / บุคลากร** | ดูรายการครุภัณฑ์ที่ตนเองเป็นผู้ถือครองรับผิดชอบ (`My Assets`), ยื่นคำขอเบิกวัสดุสิ้นเปลือง, แจ้งอุปกรณ์ชำรุด | Portal & Admin (`/inventory/my-assets`, `/inventory/supplies/request`) |
| **Asset Officer (เจ้าหน้าที่พัสดุ)** | ลงทะเบียนครุภัณฑ์, พิมพ์สติกเกอร์ QR Code, บันทึกการโอนย้ายสถานที่/ผู้ถือครอง, รับเข้า/ตัดจ่ายวัสดุสิ้นเปลือง, ตรวจนับสต็อก | Admin Console (`/inventory/assets`, `/inventory/supplies`) |

| **System Administrator** | กำหนดหมวดหมู่ครุภัณฑ์, ตั้งค่าอัตราค่าเสื่อมราคา, กำหนดสิทธิ์ และดูรายงานภาพรวมมูลค่าทรัพย์สิน | Admin Console (`/inventory/settings`, `/inventory/reports`) |

### 3. ฟังก์ชันการทำงานหลัก (Functional Requirements)

#### RF-01: ทะเบียนครุภัณฑ์และระบบรหัส (Asset Registry & Identification)
- ลงทะเบียนครุภัณฑ์พร้อมฟิลด์บังคับ: รหัสครุภัณฑ์ (`assetCode`), ชื่อครุภัณฑ์ (`nameTh`), หมวดหมู่ (`categoryId`), วันที่ตรวจรับ (`acquiredDate`), ราคาจัดซื้อ (`acquiredPrice`), แหล่งเงินงบประมาณ (`fundingSource`)
- รหัสครุภัณฑ์ต้องไม่ซ้ำกันในระดับ Tenant เดียวกัน
- สร้าง QR Code ประจำครุภัณฑ์อัตโนมัติ สำหรับพิมพ์สติกเกอร์ติดอุปกรณ์

#### RF-02: การควบคุมสถานะและวงจรชีวิต (Lifecycle State Machine)
- สถานะครุภัณฑ์:
  - `ACTIVE`: พร้อมใช้งาน
  - `IN_USE`: กำลังถูกใช้งาน
  - `UNDER_REPAIR`: อยู่ระหว่างการซ่อมบำรุง
  - `DAMAGED`: ชำรุด รอพิจารณาแทงจำหน่าย
  - `DISPOSED`: แทงจำหน่าย ตัดออกจากบัญชีสินทรัพย์แล้ว
- ทุกการเปลี่ยนสถานะต้องบันทึกประวัติลงใน `asset_transactions` พร้อมระบุผู้กระทำและเหตุผล

#### RF-03: การโอนย้ายสถานที่และเปลี่ยนผู้ถือครอง (Asset Relocation & Transfer)
- รองรับการโอนย้ายห้อง/อาคาร และเปลี่ยนตัวบุคลากรผู้รับผิดชอบ (`custodianId`)
- บันทึกประวัติจากเดิม (`fromValue`) ไปยังค่าใหม่ (`toValue`) อัตโนมัติ

#### RF-04: การบริหารคลังวัสดุสิ้นเปลือง (Consumables Inventory & Requisition)
- รายการวัสดุสิ้นเปลือง: รหัส, ชื่อ, หน่วยนับ, สต็อกคงเหลือ (`currentStock`), จุดสั่งซื้อเตือนสต็อกต่ำ (`minStock`), ราคาต่อหน่วย
- ป้องกันสต็อกติดลบ (Prevent Negative Inventory) โดยเด็ดขาด
- ระบบเบิกจ่ายวัสดุ: บุคลากรสร้างคำขอ $\rightarrow$ หัวหน้างานอนุมัติ $\rightarrow$ เจ้าหน้าที่พัสดุตัดจ่ายและส่งมอบ

### 4. เกณฑ์การตรวจรับงาน (Acceptance Criteria)
- [ ] รหัสครุภัณฑ์ต้อง Unique ในระดับ Tenant หากซ้ำต้องแจ้งเตือน Error ชัดเจน
- [ ] เมื่อกด "พิมพ์สติกเกอร์ QR" ระบบต้องสร้างหน้าพิมพ์ที่พร้อมใช้งานกับเครื่องพิมพ์ฉลาก (Label Printer)
- [ ] ไม่สามารถเบิกวัสดุสิ้นเปลืองเกินจำนวนสต็อกที่มีอยู่จริงได้
- [ ] เมื่อสต็อกคงเหลือ $\le$ `minStock` ระบบต้องแสดงสถานะสีส้ม/แดงเตือน Low Stock
- [ ] ผ่านเกณฑ์ Quality Gate: TypeScript, Lint, Depcruise, Unit Tests 100%
