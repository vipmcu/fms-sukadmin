# Product Requirements Document (PRD)
## ระบบจองห้องประชุมและยานพาหนะ (Facility & Fleet Reservation)

---

### 1. บทนำและวัตถุประสงค์ (Objective)
ระบบจองห้องประชุมและยานพาหนะเป็นฟีเจอร์หลักในการบริหารจัดการทรัพยากรส่วนกลางของคณะ เพื่อสนับสนุนการจัดกิจกรรมการเรียนการสอน การประชุมทางวิชาการ และการเดินทางไปปฏิบัติงานราชการของคณาจารย์และเจ้าหน้าที่อย่างมีประสิทธิภาพ ลดความผิดพลาดจากการจองซ้ำซ้อน และสร้างความโปร่งใสในการจัดสรรทรัพยากร

**เป้าหมายหลัก:**
1. รวมศูนย์การจองห้องประชุมและยานพาหนะไว้ในแพลตฟอร์มเดียวภายใต้สถาปัตยกรรม Modular Monolith ของคณะ
2. ป้องกันปัญหาการจองเวลาทับซ้อน (Collision Prevention) แบบ 100% ด้วยการคำนวณเวลาและระยะปลอดภัย (Buffer Time 30 นาที) อัตโนมัติ
3. ให้บริการทั้งหน้าบ้าน (Public Portal) สำหรับดูความพร้อมใช้งานและตารางงาน และหลังบ้าน (Admin Console) สำหรับการยื่นคำขอและการอนุมัติ
4. รองรับการทำงานสองภาษา (ไทย/อังกฤษ) และแยกตามหน่วยงาน (Multi-tenancy) อย่างสมบูรณ์

### 2. กลุ่มผู้ใช้งานและสิทธิ์การเข้าถึง (User Personas & Roles)

| Persona / Role | คำอธิบายและบทบาทหน้าที่ | หน้าจอหลักที่ใช้งาน |
| :--- | :--- | :--- |
| **Guest / นักศึกษา**<br>(บุคคลภายนอก) | เข้าชมข้อมูลสิ่งอำนวยความสะดวก สเปกห้อง/รถ และตรวจสอบตารางการใช้งานประจำวัน โดยระบบจะปิดบังข้อมูลส่วนบุคคล (Privacy Masking) | Public Portal (`/(portal)/facilities`) |
| **Faculty / Staff**<br>(ผู้ขอจองทรัพยากร) | อาจารย์หรือเจ้าหน้าที่ของคณะที่เข้าสู่ระบบ สามารถค้นหาห้อง/รถที่ว่าง ตรวจสอบสิ่งอำนวยความสะดวก สร้างคำขอจอง และติดตามสถานะคำขอของตนเอง | Admin Console (`/(admin)/reservations/my`, `.../calendar`) |
| **Facility Approver**<br>(เจ้าหน้าที่อาคารสถานที่) | เจ้าหน้าที่ผู้ดูแลห้องประชุม ตรวจสอบความเหมาะสมของกิจกรรม ความจุ และกดยืนยันอนุมัติ/ปฏิเสธคำขอจองห้องประชุม | Admin Console (`/(admin)/reservations/inbox`) |
| **Fleet Approver**<br>(เจ้าหน้าที่ยานพาหนะ) | เจ้าหน้าที่ผู้ดูแลรถยนต์ส่วนกลาง พิจารณาเส้นทาง ภารกิจ อนุมัติคำขอ พร้อมมอบหมายคันรถและพนักงานขับรถ (Driver Assignment) | Admin Console (`/(admin)/reservations/inbox`) |
| **System Administrator**<br>(ผู้ดูแลระบบสูงสุด) | จัดการข้อมูลห้องประชุม ยานพาหนะ ตั้งค่าปิดปรับปรุงชั่วคราว (Blackout Periods) และตรวจสอบ Audit Logs | Admin Console (`/(admin)/reservations/resources`) |

### 3. ฟังก์ชันการทำงานหลัก (Functional Requirements)

#### RF-01: แคตตาล็อกทรัพยากรและการค้นหา (Resource Catalog & Filtering)
- แสดงรายการห้องประชุมและยานพาหนะทั้งหมดที่เปิดใช้งาน (`is_active = true`)
- รองรับการคัดกรองตาม:
  - ประเภททรัพยากร: ห้องประชุม (`ROOM`) หรือ ยานพาหนะ (`VEHICLE`)
  - ขนาดความจุที่นั่ง (Capacity)
  - สิ่งอำนวยความสะดวก (เช่น เครื่องฉายโปรเจกเตอร์, ระบบ Hybrid Meeting, ไมโครโฟนไร้สาย)
  - สถานะความพร้อมใช้งานในวันและเวลาที่ระบุ

#### RF-02: การสร้างคำขอจองและการล็อกคิว (Reservation Creation & Slot Locking)
- ผู้จองต้องระบุ:
  - ทรัพยากรที่ต้องการจอง
  - วันและเวลาเริ่มต้น - สิ้นสุด (`startTime` - `endTime`)
  - วัตถุประสงค์การใช้งาน และจำนวนผู้เข้าร่วม/ผู้โดยสาร
  - ปลายทางและรายละเอียดภารกิจ (กรณีจองยานพาหนะ)
- **First-come First-served:** ระบบจะล็อกเวลาของคำขอสถานะ `PENDING` และ `APPROVED` ไม่ให้ผู้อื่นยื่นขอช่วงเวลาเดียวกันได้ทันที
- **Buffer Time:** ระบบจะบวกเวลาเตรียมความพร้อม/ทำความสะอาด/เดินทางอัตโนมัติ **30 นาที** ก่อนและหลังการใช้งาน

#### RF-03: การตรวจสอบเงื่อนไขและข้อจำกัดทางเวลา (Validation Rules)
- ต้องจองล่วงหน้าอย่างน้อย **24 ชั่วโมง** ก่อนเวลาเริ่มใช้งาน
- ห้ามเลือกวันและเวลาย้อนหลัง
- จำนวนผู้เข้าร่วมต้องไม่เกินความจุสูงสุดของห้องประชุม หรือจำนวนที่นั่งของยานพาหนะ
- ไม่อนุญาตให้จองในช่วงเวลาที่มีการประกาศปิดปรับปรุง (Maintenance Blackout)

#### RF-04: กระบวนการพิจารณาอนุมัติ (Approval Workflow)
- ระบบส่งคำขอไปยังคิวงานของเจ้าหน้าที่ตามประเภททรัพยากร:
  - คำขอห้องประชุมส่งไปยังคิวงานของเจ้าหน้าที่อาคารสถานที่
  - คำขอยานพาหนะส่งไปยังคิวงานของเจ้าหน้าที่ยานพาหนะ
- เจ้าหน้าที่สามารถ:
  - **อนุมัติ (Confirm/Approve):** ระบุหมายเหตุเพิ่มเติม และกรณีรถยนต์ **ต้องระบุชื่อพนักงานขับรถและเบอร์โทรศัพท์**
  - **ปฏิเสธ (Reject):** จำเป็นต้องระบุเหตุผลในการปฏิเสธ เพื่อแจ้งให้ผู้ขอทราบ

#### RF-05: นโยบายการยกเลิกคำขอ (Cancellation Policy)
- ผู้จองสามารถกดยกเลิกคำขอ (`CANCELLED`) ได้ด้วยตนเองล่วงหน้าอย่างน้อย **2 ชั่วโมง** ก่อนเวลาเริ่มใช้งาน
- เมื่อคำขอยกเลิกสำเร็จ ระบบจะปลดล็อกช่วงเวลาและ Buffer Time คืนสู่สถานะว่างทันที
- บันทึกเหตุผลการยกเลิกและเวลาที่ยกเลิกลงในฐานข้อมูล

#### RF-06: ปฏิทินแสดงตารางการใช้งานประจำวันหน้าบ้าน (Public Schedule Board)
- แสดงปฏิทินตารางการใช้งานแบบ Timeline (Day / Week) บน Public Portal
- **Data Privacy:** ปิดบังชื่อผู้จอง เบอร์โทรศัพท์ และรายละเอียดภายใน แสดงเฉพาะ:
  - ชื่อห้อง/ทะเบียนรถ
  - ช่วงเวลาการใช้งาน
  - หัวข้อการประชุม/ภารกิจหลักแบบย่อ
  - สถานะ (กำลังใช้งาน, จองแล้ว)

#### RF-07: การแจ้งเตือนและการติดตามสถานะ (Notifications & Audit Trail)
- แจ้งเตือนทางอีเมลหรือระบบแจ้งเตือนเมื่อ:
  - คำขอได้รับการอนุมัติ (พร้อมข้อมูลห้อง/คนขับรถ)
  - คำขอถูกปฏิเสธ (พร้อมเหตุผล)
  - มีการยกเลิกคำขอ
- บันทึกประวัติการกระทำสำคัญทั้งหมดลงในตาราง `audit_logs` กลางของระบบ

### 4. ข้อกำหนดที่ไม่ใช่เชิงฟังก์ชัน (Non-Functional Requirements)

1. **Security & Multi-tenancy:**
   - ข้อมูลทุกรายการต้องผูกกับ `tenant_id` เพื่อป้องกันการเข้าถึงข้ามองค์กรหรือข้ามคณะ
   - ตรวจสอบ Permission ผ่าน `requirePermission()` ในทุก Server Action
2. **Performance:**
   - การตรวจสอบการชนกันของเวลา (Collision Query) ต้องตอบสนองภายในไม่เกิน 150ms บน Index ช่วงเวลา (`start_time`, `end_time`)
3. **i18n & Localization:**
   - รองรับสองภาษา (ไทย/อังกฤษ) ทั้งข้อความ UI, หัวข้อ, และข้อความแจ้งข้อผิดพลาด Zod Validation
   - จัดรูปแบบวันที่และเวลาแบบ พ.ศ. สำหรับภาษาไทย และ ค.ศ. สำหรับภาษาอังกฤษ
4. **Design Compliance:**
   - ใช้ UI Components จาก `@/shared/components/liyon` สอดคล้องกับ Liyon Design System ขององค์กร

### 5. เกณฑ์การตรวจรับงาน (Acceptance Criteria)

- [ ] ผู้ใช้สามารถดูห้องและรถที่ว่างตามช่วงเวลาที่กำหนดได้ถูกต้อง
- [ ] เมื่อสร้างการจอง ระบบจะบล็อกช่วงเวลาดังกล่าวทันที ทำให้ผู้ใช้อื่นไม่สามารถกดจองเวลาทับซ้อนได้ (รวม Buffer 30 นาที)
- [ ] การจองล่วงหน้าน้อยกว่า 24 ชั่วโมง หรือเลือกเวลาย้อนหลัง จะต้องถูกปฏิเสธโดย Zod Validation
- [ ] เจ้าหน้าที่สามารถกดอนุมัติการจองห้อง และสำหรับยานพาหนะต้องบังคับกรอกชื่อคนขับก่อนกดยืนยัน
- [ ] ผู้จองสามารถกดยกเลิกได้ก่อนเริ่มงาน 2 ชั่วโมง และช่วงเวลาจะถูกปลดล็อกให้คนอื่นจองได้ทันที
- [ ] หน้า Portal สาธารณะแสดงปฏิทินตารางงานโดยไม่เปิดเผยชื่อผู้ขอจอง
- [ ] ผ่านการทดสอบ `npm run check` ครบทุกขั้นตอน (type-check, lint, deps:check, tests)
